# SafeMeal Agent 架构说明

## 项目定位

这是一个可在单机 Docker 环境完整演示的垂直食谱 Agent。目标是展示 Agent 编排、混合数据检索、确定性安全约束、三层记忆、Trace 和 LLM Judge，而不是模拟大规模生产平台。

## 数据与工具边界

- MySQL：会话、消息、用户长期记忆和情景摘要，以及结构化菜谱数据。
- Milvus：TXT、Markdown、PDF 文档的语义检索。查询先扩大召回，再 Rerank，并限制每个文档的片段数量，从而支持多文档归纳。
- Neo4j：只保留食谱、食材、忌口关系的参数化推荐工具。模型不能提交任意 Cypher。
- Redis：只实现 HTTP Token Bucket。Agent 和工具并发使用本地 semaphore。
- LLM Provider：单 Provider，使用 SDK 自带有限重试，不做跨供应商故障切换和熔断。

## 三层记忆

1. 工作记忆：当前请求和最近若干条消息。
2. 情景记忆：长对话压缩出的摘要，持久化到 `user_memories`，后续会话按相关性加载。
3. 语义记忆：过敏、忌口、偏好、设备与健康目标等长期画像。

硬约束始终由领域代码校验；模型不能覆盖过敏与忌口规则。

## 可观测与评测

Agent Trace 的 Pydantic 数据模型保持稳定，落盘实现简化为单机 append-only JSONL，并提供内部查询接口。评测保留检索、正确性、忠实度等直接指标以及 LLM Judge，删除质量门禁、分片恢复、基线回归和监控告警平台。

## 面试表述

可以重点说明三个取舍：

1. 用 Milvus 的候选扩召回、Rerank 和按文档轮询替代额外的 LightRAG，降低组件复杂度，同时保留跨文档证据覆盖。
2. 把 Neo4j 收敛成领域工具，既体现图谱建模，也避免开放通用查询带来的不确定性。
3. 保留三层记忆、Trace 和 LLM Judge 作为 Agent 质量亮点；删除分布式队列、熔断、监控平台等单机项目无法有效证明的代码。
